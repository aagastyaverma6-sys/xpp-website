What is X++? #

X++ is an intent-driven language: you write strict pseudocode, type one command, and it runs. Under the hood it's a real engine — a zero-dependency C++17 virtual machine (ZITR), a bytecode compiler (ZCOM), and a native AOT backend that compiles your program through C++ to machine code (ZJIT).

The design rule that shapes everything: no types to annotate, no pointers, no manual memory management, no build files. The VM garbage-collects automatically.

Same pseudocode, three engines. A program written for v0.3 runs unchanged on the native VM today — and the exact same source also runs in this website's playground.

Your first program #

Install X++ (see the home page), open any editor, and write:

RNM=ZITR

out "hello world"

Then run it with one command:

x run hello.xp
hello world

The first line, RNM=ZITR, is a directive that picks the engine. It's optional — x auto-detects it and defaults to the native VM. Everything after a # is a comment.

Package Manager (XPM) #

X++ v0.4.5 introduces a decentralized package manager. Install any library directly from its GitHub repository without centralized registries:

# Install from any GitHub repo into ./xpp_packages/
x install github.com/user/library
x install user/library

# Install all dependencies recorded in xpp.json
x install

# Uninstall a package
x remove library

# List all local and global packages
x list

# Initialize a new X++ package
x init my_app

Import installed packages or standard libraries directly in your code with use or import:

use mathX
use "github.com/user/library"

out mathX.sqrt(100)
out mathX.pi

Mathematical Libraries #

Full suite of mathematical libraries verified across all 5 RNMs (XCOM, XITR, ZCOM, ZITR, ZJIT):

  • mathX: Trigonometry (sin, cos, tan), hyperbolic, combinatorics (factorial, comb, perm), statistics (mean, median, variance), constants (pi, e, tau, phi), gcd, lcm, prime testing.
  • Xsci: Scipy counterpart. Optimization (minimize, root), curve fitting (curve_fit), numerical quadrature (quad, trapz, simpson), 1D interpolation (interp1d), FFT/IFFT, filters, Bessel functions, and probability distributions (norm_pdf, norm_cdf, poisson_pmf).
  • Xnum: Numpy counterpart. Multidimensional NDArray, zeros, ones, arange, linspace, matrix reshaping, matrix multiplication (dot, matmul), axis reductions (sum, mean, std, min, max).
  • Xlin: Linear algebra. Determinants (det), matrix inversion (inv), system solver (solve), trace, vector norm, QR decomposition, LU decomposition, and eigenvalues/eigenvectors (eig).
  • XCAS: Computer Algebra System. Symbolic expression trees, symbolic differentiation (diff), elementary integration (integrate), simplification (simplify), substitution (subst), and equation solving (solve).
  • XCalculus: Complete calculus suite. Limits (limit), nth-order derivatives (derivative), partial derivatives, Jacobian, Hessian, single/double/triple definite integrals, gradient, divergence, curl, and Laplacian.
  • Xplotlib: Matplotlib counterpart. 2D lines/scatters/bars/histograms, 3D plots & surfaces, 4D animated frames, interactive GUI window, SVG output, and high-res ASCII terminal plots.
use mathX
use Xnum
use Xlin

out "sqrt:", mathX.sqrt(144)
out "pi:", mathX.pi

# Vector & Matrix
m = [[1, 2], [3, 4]]
out "det:", Xlin.det(m)
out "zeros:", Xnum.zeros([2, 2])

Web Related Libraries #

  • ScrapeX: Web scraping module. HTTP fetch/get/post, HTML DOM parser, CSS selector queries (select, select_one), table extractors (extract_tables), link extractors, and image extractors.
  • XWeb: Full-stack web module. Semantic HTML tag builders (div, p, h1..h6, button, a), responsive CSS compiler (style, stylesheet), JS injection, route handling, and static site export.
  • XWview: Desktop webview library. Embedded web windows, loading HTML/URLs, executing JS, and bidirectional communication.

Development & Creative Libraries #

  • GraphiX: 2D vector and canvas graphics engine. Primitives (rect, circle, line, polygon, text, path), transforms, CSS styling (apply_css), and SVG rendering.
  • XGUI: Ultra-modern desktop GUI library. Component architecture (window, card, button, text_input, slider), theme presets (modern-dark, glassmorphism, neo-brutalism), custom CSS/JS injection, and reactive state.
  • TerminX: Terminal UI toolkit. ANSI colors, bold/dim/italic, bordered boxes (box), formatted tables (table), progress bars, and interactive prompts.
  • Xin: Mouse and keyboard input detection (getch, key polling, mouse coordinates, click listeners).
  • GameX: Full 2D & 3D game engine. Physics, AABB/circle collisions, game loops, delta timing, and asset loaders for:
    • 2D Sprites: PNG, PSD, TGA, WebP, GIF, SVG, DDS, JSON, JPEG, ASEPRITE.
    • 3D Models: FBX, OBJ, GLTF/GLB, BLEND, MAX, MAYA, USD/USDA, 3DS, COLLADA (DAE), STL.
  • Xanmin8: Mathematical animations (Manim counterpart). Vector MObjects (Circle, Square, Line, Text, MathTex), animations (Create, FadeIn, Transform), scenes, and video/SVG timeline export.

Printing — out #

out prints values separated by spaces, one line at a time:

RNM=ZITR

out "hello", "world"
out 1, 2, "three"
out [1, 2, 3]
out {"name": "xpp", "version": "0.4.1"}
hello world
1 2 three
[1, 2, 3]
{"name": xpp, "version": 0.4.1}

(Yes — string values inside lists and dicts print without quotes. That's the native VM's display style, faithfully reproduced here.)

Variables & values #

Assign with =. No declarations, no types. Reading a variable that was never set gives nil:

RNM=ZITR

name = "Aagastya"
version = 0.4
awesome = true
missing = nothing_here

out name, version, awesome, missing
out type(name), type(version), type(awesome), type(missing)
Aagastya 0.4 true nil
string float true nil
  • Ints and floats — 7 / 2 is 3.5 (true division); 2 + 2 stays an int.
  • Booleans — true / false.
  • nil — the “nothing” value; it is falsy, and it propagates through arithmetic (nil + 1 is nil).
  • Empty things are falsy: 0, "", [], {}, nil.

Dicts #

Dicts map string keys to values and keep insertion order. Use ["key"] or dot access:

RNM=ZITR

user = {"name": "Aagastya", "lang": "X++"}
user.version = "0.4.1"          # dot assignment
user["os"] = "Windows"          # bracket assignment

out user
out user.name                   # dot read
out user["lang"]                # bracket read
out len(user)
out keys(user)
out values(user)
out contains(user, "os")

out get(user, "missing")            # nil if absent
out get(user, "missing", "nope")    # with a default

Decisions — if / elif / else #

Blocks open with : and close with end. Indentation is for humans — the VM doesn't require it.

RNM=ZITR

fn classify(n):
  if n < 0:
    return "negative"
  elif n == 0:
    return "zero"
  elif n < 10:
    return "small"
  else:
    return "big"
  end
end

loop n in [-5, 0, 7, 99]:
  out n, "->", classify(n)
end
-5 -> negative
0 -> zero
7 -> small
99 -> big

Loops #

Three loop flavours, plus break and continue:

RNM=ZITR

# 1) counting loop — inclusive of both ends, optional step
loop i from 1 to 10 step 3:
  out i
end

# 2) for-each over a list (or a string!)
loop fruit in ["apple", "banana", "cherry"]:
  out "I like", fruit
end

# 3) while — with break and continue
i = 0
while true:
  i = i + 1
  if i > 6:
    break
  end
  if i % 2 == 0:
    continue
  end
  out i, "is odd"
end
1
4
7
10
I like apple
I like banana
I like cherry
1 is odd
3 is odd
5 is odd

Negative steps count down: loop i from 10 to 0 step -2: gives 10, 8, 6, 4, 2, 0.

Functions #

Define with fn, return with return (returns nil if you don't). Functions are available everywhere — even before their definition — and recursion is a first-class citizen:

RNM=ZITR

out shout("x++")     # called before the definition below

fn shout(word):
  return word + "!"
end

fn factorial(n):
  if n <= 1:
    return 1
  end
  return n * factorial(n - 1)
end

out factorial(10)

# mutual recursion works too
fn is_even(n):
  if n == 0:
    return true
  end
  return is_odd(n - 1)
end
fn is_odd(n):
  if n == 0:
    return false
  end
  return is_even(n - 1)
end

out is_even(10), is_odd(7)
x++!
3628800
true true
Scoping is Python-like: a name assigned anywhere inside a function is local to it; every other name resolves to the global scope. The native VM recurses 20,000+ frames deep thanks to its flat dispatch loop.

Errors — safe / fail #

Wrap risky code in safe: … fail e: … end. Errors propagate out of nested function calls until a safe catches them:

RNM=ZITR

fn risky(n):
  return 100 / n       # division by zero is a runtime error
end

loop n in [4, 0]:
  safe:
    out "100 /", n, "=", risky(n)
  fail e:
    out "caught:", e
  end
end
100 / 4 = 25
caught: division by zero

Uncaught errors stop the program with X++ [ZITR] error: ….

Input & files #

in reads one line (optionally with a prompt); read loads a whole file; write(…) saves one:

RNM=ZITR

# in the playground, `in` reads from the Input box
name = in "What is your name? "
n = int(in "Favourite number? ")

out "Hello,", name
if n % 2 == 0:
  out n, "is even"
else:
  out n, "is odd"
end
What is your name? Favourite number? Hello, Aagastya
42 is even
Note: in prints its prompt inline, without a newline, the moment it reads — so both prompts above appear before the outputs. That's exactly what the native VM does in a terminal.
RNM=ZITR

# in the browser this uses a sandboxed in-memory disk —
# natively it is your real filesystem
write("notes.txt", "X++ makes pseudocode real")
out read "notes.txt"
X++ makes pseudocode real

Run modes & RNM #

The RNM=… directive at the top of a file picks an engine. Missing or unknown? x auto-detects and defaults to ZITR, the native VM.

DirectiveEngineNeedsUse when
RNM=ZITRNative stack VM (default)xppvm (auto-built)Everyday running
RNM=ZCOMBytecode AOTxppvmYou want to inspect/port .xbc
RNM=ZJITNative AOT (fastest)xppvm + C++ compilerBenchmarks & hot loops
RNM=XCOM / RNM=XITRLegacy v0.3 enginesPythonOld programs
RNM=ITRAI intent compilerOpenRouter keyTurning English steps into code
 
x run app.xp                    # native VM (auto ZITR)
x run app.xp --mode ZJIT        # native AOT — fastest
x compile app.xp --emit-xbc app.xbc
x disasm app.xbc                # see the bytecode
xppvm zitr app.xp               # run with no Python at all

The web playground #

The playground runs the same strict-pseudocode language entirely in your browser — a faithful port of the ZITR VM semantics, quirks included. A few honest differences:

  • It's an interpreter, not the native VM — great for learning, ~100× slower than ZJIT for hot loops.
  • Recursion depth is limited to roughly 1,500 frames (the native VM handles 20,000+ with its flat dispatch loop).
  • read / write use a sandboxed in-memory disk instead of your filesystem.
  • Runs time out after 8 seconds to keep infinite loops from freezing the page.

When your program outgrows the sandbox, install the real thing ↗ — same language, real speed.
